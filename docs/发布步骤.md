# 发布到 GitHub 的步骤

仓库内容已经准备好，按下面顺序执行即可。命令都是 PowerShell（Windows）。

---

## 0. 推送前自查（最重要的一步）

确认仓库里**没有**任何真实密钥：

```powershell
cd C:\Users\hengt\Desktop\DangoMusic-QQ
git init -b main
git add .
git grep -n "AIzaSy" ; git grep -n "firebaseio.com" ; git grep -n "togetherlin"
```

三条命令都**应该没有输出**。如果有输出，说明某个文件里还带着你的 Firebase 项目信息，
先把它改成占位符、并确认 `.gitignore` 覆盖了它（`firebase.properties` 已在忽略列表里）。

> 记住：`apiKey` 泄露等于把数据库钥匙公开，别人可以读写你的库、刷爆免费额度。

---

## 1. 建空仓库

打开 <https://github.com/new>：

- Repository name：`DangoMusic-QQ`（或你喜欢的名字）
- **不要**勾 `Add a README file`、`Add .gitignore`、`Choose a license`——本地都已经有了，勾了会产生冲突
- 建议 Public；如果要保留后续商业化可能，先 Private 也行

## 2. 推送源码

```powershell
cd C:\Users\hengt\Desktop\DangoMusic-QQ
git add .
git commit -m "Dango Music QQ 音乐版 1.5.1-qqmusic：替换实现、补丁管线与文档"
git remote add origin https://github.com/<你的用户名>/DangoMusic-QQ.git
git push -u origin main
```

首次推送会弹浏览器登录 GitHub（或用 Personal Access Token 作为密码）。

> 如果 `git` 没装：<https://git-scm.com/download/win>，装完重开终端。

## 3. 填写仓库信息

仓库页右侧 `About` 齿轮：

- Description：`在 Minecraft 里听 QQ 音乐 · DangoMusic 的 QQ 音乐改版（1.20.1–26.3，Fabric/Forge/NeoForge）`
- Website：留空
- Topics：`minecraft` `minecraft-mod` `fabric` `forge` `neoforge` `qqmusic` `music-player`

`Settings` → `General` → `Features`：建议勾上 `Issues`（方便收集兼容性反馈）。

## 4. 发 Release（上传 10 个 jar）

`Releases` → `Draft a new release`：

- **Tag**：`v1.5.1-qqmusic`（新建 tag，target 选 `main`）
- **Release title**：`1.5.1-qqmusic`
- **说明**：直接粘贴下面这段

```markdown
DangoMusic 的 QQ 音乐改版，基于上游 1.5.0 的 10 个平台 jar 逐一适配。

## 下载（只放一个）

| Minecraft | Fabric | Forge / NeoForge |
| --- | --- | --- |
| 1.20.1 | `DangoMusic-1.5.1-qqmusic+1.20.1-fabric.jar` | `…+1.20.1-forge.jar` |
| 1.21.1 | `…+1.21.1-fabric.jar` | `…+1.21.1-neoforge.jar` |
| 1.21.11 | `…+1.21.11-fabric.jar` | `…+1.21.11-neoforge.jar` |
| 26.2 | `…+26.2-fabric.jar` | `…+26.2-neoforge.jar` |
| 26.3 | `…+26.3-fabric.jar` | `…+26.3-neoforge.jar` |

装过原版 DangoMusic 的请先删除（id 都是 dangomusic，会冲突）。Fabric 端需要 Fabric API。

进游戏按 `M` → `Log in to QQ Music` → 手机 QQ 扫码。登录态约 3 天过期，过期后重新扫码。

## 一起听

需要自备 Firebase 项目（Realtime Database + 匿名登录），配置方法见仓库 `docs/一起听.md`。
房间内所有人必须使用同一个项目，并且需要代理才能连上 Google 的域名。

## 校验

`SHA256SUMS.txt` 里是全部产物的哈希，可用 `sha256sum -c SHA256SUMS.txt`（Linux）或
`Get-FileHash`（PowerShell）核对。本仓库的构建管线是可复现的：
用同样的上游 jar 执行 `tools/build_all.py` 能得到逐字节相同的产物。

## 说明

非官方改版，与腾讯 / 网易云音乐 / Mojang 无关联，仅供学习与自用。
原始项目 https://github.com/Sorihiko/DangoMusic ，本改版同样按 GPL-3.0 分发。
```

然后把这些文件拖进 `Attach binaries`：

- `C:\Users\hengt\Desktop\DangoMusic-QQ音乐版\jars\` 里的 **10 个 jar**
- `C:\Users\hengt\Desktop\DangoMusic-QQ音乐版\SHA256SUMS.txt`

勾上 `Set as the latest release` → `Publish release`。

## 5. 验证发布结果

```powershell
# 新克隆一份，确认别人拿到的东西能构建
git clone https://github.com/<你的用户名>/DangoMusic-QQ.git D:\tmp\DangoMusic-QQ
cd D:\tmp\DangoMusic-QQ
python tools/fetch_upstream.py           # 网络能直连时不用加 --proxy
python tools/build_all.py 26.3-fabric
python tools/verify_all.py 26.3-fabric
# 产物的 sha256 应与 Release 里 26.3-fabric 那一行完全一致
```

## 6. 以后更新上游版本时

1. 改 `tools/fetch_upstream.py` 里的 `UPSTREAM_VER`（例如 `1.5.1` → `1.6.0`）
2. 跑 `python tools/inspect_upstream`（可选）：确认目标类仍在、枚举顺序与文案未变
3. `python tools/build_all.py` → `python tools/verify_all.py`
4. 若上游改了内部签名，编译会失败——那就是需要按报错逐个修 `src/` 的地方
5. 改 `CHANGELOG.md`、打新 tag、重复第 4 步

## 7. 注意事项

- **不要**把 `firebase.properties`（含真实 apiKey）提交进仓库或贴进 Issue。
- **不要**把上游的 jar 一起提交进仓库（Release 附件即可）；仓库只放源码、工具、文档。
- 仓库已包含 GPL-3.0 全文（`LICENSE`），改动说明写在 `README.md` 的「修改说明」一节，
  这是 GPL-3.0 第 5 条对分发修改版的要求。
